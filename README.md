# SIH26 · 레이트 바이브 코딩 프로젝트

HTML·CSS·순수 JavaScript로 만든 고등학교 정보 수업용 전시판입니다. 실행 시 서버 API·DB·로그인·외부 CDN·AI API를 사용하지 않습니다. 목록에는 스크린샷 카드를 표시하고, 카드를 누르면 선택한 작품 하나가 상세 화면의 sandbox iframe에서 즉시 실행됩니다.

## 전시판 글꼴

제목·작품 카드 제목·SIH26 로고는 **Paperlogy Bold(700)**, 본문·메뉴·버튼은 **Wanted Sans**입니다. 공식 저장소의 WOFF2 원본을 `assets/fonts/`에 포함하고 Pages 산출물에도 복사합니다. 외부 폰트 CDN 없이 작동하며 `font-display: swap`을 적용했습니다. 두 폰트의 SIL OFL 1.1 라이선스와 고정된 출처는 같은 폴더에 동봉했습니다. 학생 프로그램의 독립된 HTML 내부 글꼴은 변경하지 않습니다.

색은 Uiverse.io의 Prismfield 카드·버튼(작성자 uiverse-astronaut, MIT License, Copyright (c) 2023 Uiverse.io)을 바탕으로 수정했습니다. 라이선스 전문은 `assets/style.css` 상단 주석에 있습니다. 무채색 바탕(#faf9f6·#ffffff·먹색 #0b0b0f)에 프리즘 그라데이션은 헤더 아래 3px 띠, 카드에 마우스를 올렸을 때의 테두리, 강조 버튼(연두)의 번짐에만 씁니다. 프리즘 색은 글자색으로 쓰지 않습니다. 움직임 줄이기 설정에서는 떠오르는 효과를 끕니다.

화면 규칙(`assets/style.css` 상단 토큰): 본문 17px·줄 간격 1.7·`word-break: keep-all`(한글 단어 단위 줄바꿈), 읽는 글자는 13px 이상, 간격은 4·8·12·16·24·32·48·64px, 둥글기는 조작 요소 8px·카드와 영역 12px·키 표시 같은 작은 표식 4px.

검색창은 Prismfield 검색(같은 출처·라이선스)을 바탕으로 돋보기 아이콘과 `/` 키 표시를 두고, 포커스되면 3px 프리즘 링(크기 변화 없음)으로 바뀝니다. 목록 화면에서 입력 중이 아닐 때 `/`를 누르면 검색창으로 이동합니다. 키 표시는 키보드가 없는 기기와 입력 중에는 숨깁니다. 입력 글자는 휴대폰 확대 방지를 위해 16px, 테두리는 흰 바탕 대비 3:1 이상 색을 유지합니다.

## 학생이 사용하는 화면

- 목록: 검색, 반 선택, 작품 카드. 학번순으로 표시하며 카드를 누르면 바로 실행 화면으로 이동합니다. 결과 수는 평소 ‘작품 N개’, 조건 사용 시 ‘검색 결과 N개’로 표시합니다. 검색·반 조건이 있을 때만 ‘검색 초기화’가 나타나며 초기화 후 검색창으로 포커스가 돌아갑니다. 카드 학번은 14px로 강조합니다(카드 전체가 링크라 화살표는 두지 않음). 이 탭에서 이미 연 작품 카드에는 연두 점과 ‘봄’이 표시됩니다(sessionStorage, 탭을 닫으면 사라져 공용 PC의 다음 학생에게 남지 않음).
- 작품 화면: 상단에 제목·한 줄 설명과 **HTML 다운로드**·**새 탭 실행**(강조 버튼), 얇은 **작품 미리보기** 제목 줄 아래 넓은 자동 실행 iframe. 미리보기 제목 줄에 ‘저장·다운로드가 안 되면 새 탭 실행’ 안내와 테두리 있는 **↻ 다시 시작** 버튼을 둡니다. 실행 영역 아래에 **이전 작품·다음 작품**(목록에서 고른 검색·반 조건의 학번순, 조건 밖 작품이면 전체 학번순)과 학번·반·상태·수정일을 배치합니다.
- 작품 화면 오류: 잘못된 학번·미등록 작품은 이유를 그대로 알리고, 목록 파일을 못 읽으면 오류 코드 대신 연결 확인 안내와 **다시 시도** 버튼을 보여 줍니다.
- 하단 정보: ‘마지막 업데이트 날짜 · 버전(커밋 앞 7자리)’만 표시합니다.
- 디자인 시안(design.html): ①컬러셋 16개(밝은 바탕 13·어두운 바탕 3, 색만) → ②2026 트렌드 14개(기본+13종: 모양·배치·움직임·질감·글꼴, 견본은 고른 색으로 그림, 쓰는 곳·어울리는 작품·피할 곳 안내, 다크 테크는 밝은 컬러셋을 어두운 짝으로 자동 전환, 움직임은 prefers-reduced-motion에서 멈춤) → ③추가 요청 → ④완성된 디자인 수정 프롬프트 복사. PC에서는 오른쪽 미리보기만 따라 내려오고, 휴대폰에서는 한 번 고른 뒤부터 오른쪽 아래에 작은 미리보기가 떠 있습니다(전체 미리보기가 보이면 숨김, 누르면 이동, 접기 가능). 고른 값과 ③추가 요청 글은 localStorage(sih26-design-v2)에 기억합니다.
- 진행 대시보드(dashboard.html, 전시판 헤더 ‘대시보드’): 교사가 진행 상황을 보기 위한 화면. 학번과 단계 배지 6칸(PRD·1회·2회·3회·4회 개선·디자인)만 보여 주고 이름·작품 제목은 쓰지 않습니다. 만점 기준은 여섯 가지 모두이며, 반마다 ‘만점 / 1개 남음 / 2개 남음 / 3개 이상 남음’으로 묶습니다. 진행 단계는 누적(3회 개선이면 PRD·1·2회도 완료, 5회 개선은 4회까지 완료)으로 보고, 디자인은 `<meta name="design">`이 있으면 완료이며 학생 강조색 칩으로 표시합니다. projects.json만 읽고 따로 저장하지 않습니다(반 선택·‘만점 아닌 학생만’은 sessionStorage).
- 상세의 큰 스크린샷·미리 실행 버튼·기획서 보기·AI 상담·코드 복사·높이/종료 메뉴와 목록의 정렬 메뉴·중복 실행/다운로드 버튼을 제거했습니다.
- 검색·반·더 보기·스크롤은 목록으로 돌아오면 복원됩니다. iframe의 저장·팝업·다운로드 제한이 있는 경우 새 탭 실행을 사용합니다.

## 현재 저장소와 최초 게시

확인한 origin은 `github.com/jungbucks/sih26`입니다. 구현 시작 시 원격에는 커밋·브랜치가 없어서 기본 브랜치를 확인할 수 없었습니다. `main`이라고 가정해 워크플로를 고정하지 않았습니다.

1. 구현 파일을 저장소에 첫 커밋으로 올리고 GitHub에서 기본 브랜치를 지정합니다. 학생 HTML은 교사가 확인한 코드만 기본 브랜치에 반영합니다.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택합니다.
3. Actions 사용을 허용하고 `github-pages` 배포 환경의 보호 규칙을 확인합니다. 기본 브랜치만 배포할 수 있게 제한하는 것을 권장합니다.
4. 기본 브랜치 push 또는 **Actions → Build and publish exhibition → Run workflow**를 실행합니다.
5. build 성공 후 deploy 성공과 **게시 완료** 요약의 실제 주소를 확인합니다. 빌드 성공만으로 게시되었다고 판단하지 않습니다.

기본 Pages 규칙에 따른 예상 주소는 `https://jungbucks.github.io/sih26/`입니다. 실제 게시와 이 주소의 응답은 아직 확인되지 않았습니다. 배포 출력 주소가 최종 근거입니다. 외부 PR 실행 트리거와 `pull_request_target`은 없습니다. 빌드는 contents 읽기만, 배포는 contents 읽기·pages 쓰기·id-token 쓰기만 사용합니다. 동일 게시 흐름은 이전 실행을 취소하며 배포 직전 기본 브랜치 최신 SHA인지 API로 재확인합니다. 그 직후 새 push가 오는 극히 짧은 경쟁 구간까지 원자적으로 막는 GitHub Pages 기능은 없으므로 concurrency 취소도 함께 사용합니다.

전시판 등록 확인용으로 두었던 `10100` 숫자 야구 테스트 작품과 `npm run test:baseball` 검사는 2026-10-13 사용자 요청으로 삭제했습니다(Git 이력에 남아 있음).

## 작품 추가·교체·삭제

루트 바로 아래 **숫자 5자리 폴더**의 `index.html`만 등록합니다. 앞자리 0을 보존합니다.

```text
20100/index.html
20101/index.html
prd/20100.md          # 선택, 공개용 원문
project-meta.json    # 선택, 교사 덮어쓰기
```

- **추가:** 학번 폴더에 CSS·JS와 필요한 이미지/데이터를 내장한 단일 `index.html`을 넣고 기본 브랜치에 push합니다.
- **수정:** 해당 파일을 완전한 HTML로 교체합니다. 다른 학생 파일은 건드리지 않습니다.
- **삭제:** 폴더 또는 그 안의 index.html을 삭제하고 push합니다. 매번 현재 파일로 산출물을 새로 조립하므로 예전 캐시가 작품을 다시 등록하지 않습니다.
- **이름 변경:** 기존 학번 삭제 + 새 학번 등록으로 처리합니다.
- **임시 비공개:** 무한 루프 등 문제가 재현되면 `index.html`을 `index.disabled.html`로 이름 변경하거나 학생 폴더를 숫자 5자리가 아닌 이름으로 바꿉니다. 새 게시 후 목록과 공개 산출물에서 제외됩니다. 공개 저장소의 Git 이력까지 비공개가 되는 것은 아닙니다.
- 루트 `20100.html`, 하위 폴더 내부 작품, 루트 전시판은 자동 등록하지 않습니다. 폴더만 있거나 HTML이 2MiB를 초과하면 이유와 학번을 보고하고 나머지를 처리합니다. 심볼릭 링크는 작품으로 사용하지 않습니다.
- 등록 가능한 작품이 **200개 초과**하면 전체 빌드를 실패시킵니다. 임의로 일부를 누락해 게시하지 않습니다.

파일 하나를 내려받아 오프라인에서 기본 기능을 쓸 수 있도록 외부 라이브러리·외부 리소스에 의존하지 마세요. 촬영 중 외부 요청은 차단합니다. 빌드 도구는 학생 작품의 모든 실행 경로가 오프라인에서 동작하는지 자동으로 증명하지 않습니다.

### HTML 메타 예시

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>나의 시간표 도우미</title>
  <meta name="description" content="하루의 수업과 준비물을 정리합니다.">
  <meta name="class" content="2학년 1반">
  <style>/* 스타일 */</style>
</head>
<body>
  <h1>시간표 도우미</h1>
  <p>수업을 추가해 보세요.</p>
  <script>/* 예시 데이터·상태·처리 함수·화면 갱신·이벤트 */</script>
</body>
</html>
```

반은 학번에서 추론하지 않습니다. 상태도 자동 추론하지 않습니다. 수정일은 학생 index.html의 마지막 Git 커밋 시각이며 한국 시간으로 표시합니다. 미커밋 파일은 ‘수정일 미확인’입니다. 사이트 빌드 시각으로 대체하지 않습니다.

### 선택 JSON과 검증 규칙

```json
{
  "20100": {
    "title": "시간표 도우미",
    "description": "친구들의 의견을 반영한 시간표 프로그램입니다.",
    "class": "2학년 1반",
    "status": "개선 중",
    "changes": "빈 입력 안내와 키보드 이동을 개선했습니다."
  }
}
```

최상위는 학번을 키로 하는 객체, 각 값도 객체입니다. 허용 필드는 아래뿐이며 **모두 문자열**입니다. JSON 구문·구조·자료형·허용값·길이 오류는 게시 전 전체 실패입니다. 공백 연속(줄바꿈 포함)은 한 칸으로 합치고 앞뒤 공백을 제거합니다. 길이는 정리 후 Unicode 코드 포인트 수입니다.

| 필드 | 최대 길이 | 비었거나 없을 때 |
|---|---:|---|
| title | 100 | 프로젝트 학번 |
| description | 300 | 프로그램을 실행해 확인해 보세요. |
| class | 40 | 미분류 |
| status | 10 | PRD / 1회 개선 ~ 5회 개선 (이전 값 첫 버전 / 개선 중 / 개선 완료도 허용). 학생 HTML의 `<meta name="status" content="1회 개선">`로도 지정하며, 허용값이 아니면 무시. 목록 카드의 반 칩 옆 회색 배지와 작품 화면 정보 줄에 표시 |
| design | 60 | 미표시. 학생 HTML의 `<meta name="design" content="컬러셋 … · 트렌드 … · #강조색">`로만 지정. 디자인 개선을 반영했다는 표시이며 단계(status)는 바꾸지 않음. 단계 배지 옆에 강조색 바탕의 `디자인` 칩을 붙이고, 칩 툴팁과 정보 줄에 컬러셋·트렌드를 표시 |
| changes | 500 | 미표시 |

HTML에서 추출한 값에도 같은 공백 규칙을 적용하고 상한까지 잘라 표시합니다. 선택 JSON은 초과 시 오류를 내므로 교사가 수정할 수 있습니다. JSON 값이 HTML 값을 덮어씁니다. 빈 덮어쓰기 값은 기본값으로 돌아갑니다. 존재하지 않는 작품의 유효한 메타는 작품을 새로 등록하지 않습니다. 제목·설명은 `textContent`로 표시합니다.

### 공개 기획서 예시

`prd/20100.md`:

```markdown
# 시간표 도우미
- 목적: 준비물을 잊지 않도록 돕기
- 대상: 같은 반 학생
- 핵심 기능: 시간표 입력, 준비물 목록
- 확인할 상황: 빈 입력, 중복 수업, 저장 불가
- 개인정보: 이름과 연락처를 수집하지 않음
```

기존 공개 기획서 파일과 생성 목록의 PRD 경로는 유지하지만, 간소화한 학생 화면에는 기획서 메뉴를 표시하지 않습니다.

## AI 검토 의견 (feedback.json)

작품 화면의 미리보기 아래에 **AI 검토 의견** 카드 1~3장을 표시합니다. 기획서를 보고 작품을 만든(또는 개선한) AI가 다음 개선 방향을 제안하는 디지털 메모입니다. 데이터는 저장소 최상위 `feedback.json` 하나에 학번별로 둡니다. 학생 HTML은 건드리지 않습니다.

```json
{
  "20112": {
    "stage": "PRD",
    "items": [
      { "title": "출시일 당일은 어느 목록일까?", "body": "지금은 ‘구매 가능’으로 분류해요. 어떤 기준이 맞는지 정해 보세요." }
    ]
  }
}
```

- `stage`: 이 의견이 기준으로 삼은 단계. status 허용값(PRD, 1회 개선 ~ 5회 개선)만 사용합니다.
- `items`: 1~3개. `title` 60자, `body` 300자 이내(공백 정리 후 코드 포인트 수).
- 형식이 틀리면 게시 전 전체 실패합니다. 항목이 없는 학번은 카드 영역을 숨깁니다.
- 공개 저장소이므로 기획서 원문·학생 이름을 옮기지 말고, 작품에서 보이는 동작 기준으로 씁니다.
- 개선할 때마다 해당 학번 항목을 새 단계 의견으로 **교체**합니다(이전 의견은 Git 이력에 남습니다).

## 제작 기록 (V1, V2 …)

작품 화면 아래에 **제작 기록**을 자동으로 표시합니다. 사람이 적지 않습니다. 빌드할 때 `학번/index.html`의 Git 커밋을 오래된 순으로 읽고, 각 커밋 시점 HTML의 `<meta name="status">` 값을 봅니다.

- 같은 단계가 이어지는 커밋은 한 버전으로 묶습니다. 단계가 바뀌면 새 버전(V2, V3 …)이 생깁니다.
- 단계가 같아도 `<meta name="design">`이 처음 붙은 커밋은 새 버전(예: `2회 개선 · 디자인`)으로 나눕니다.
- 단계 메타가 없는 커밋은 다음 버전에 합치고, 마지막 커밋들에 단계가 없으면 직전 버전의 수정으로 봅니다.
- 날짜는 그 버전의 첫 커밋~마지막 커밋(한국 시간, 같은 날이면 하루만)입니다. 마지막 줄에 ‘현재’를 표시합니다.
- 따라서 개선할 때 학생 HTML의 status를 `1회 개선`처럼 올려 커밋하기만 하면 기록이 한 줄 늘어납니다. Actions는 `fetch-depth: 0`으로 전체 이력을 받습니다.

## 교사 처리 결과와 재촬영

Actions 실행 Summary에서 실행 SHA, 등록·제외 수, 새 촬영·캐시·실패 수, 제외·실패 학번과 이유, 후속 조치를 확인합니다. 자세한 이벤트 기록은 `build-report` 아티팩트에 있습니다. 로컬 결과는 `.cache/build-report.json`입니다. 내부 로그는 사이트에 포함하지 않습니다.

수동 workflow의 `force` 입력:

- 빈 값: 일반 갱신, 성공 캐시 재사용
- `20100`: 그 학번만 강제 재촬영
- `all`: 전체 강제 재촬영

개별 촬영 실패는 이미지 없음 대체 화면으로 표시하지만 정보·실행·다운로드는 유지합니다. 실패 이미지는 캐시하지 않아 다음 실행에서 재시도합니다. 메타 오류·200개 초과·브라우저 설치 오류 등 전체 실패 시 배포 작업은 실행되지 않아 기존 게시본을 유지합니다. 잘못된 변경은 GitHub 커밋의 **Revert** 또는 `git revert <커밋>` 후 기본 브랜치에 반영합니다. 공유 이력을 강제로 초기화하지 마세요.

## 촬영·캐시·공개 산출물

Actions는 Playwright **1.58.2**, `mcr.microsoft.com/playwright:v1.58.2-noble`, Node **22.16.0**을 사용합니다. 이미지에 포함된 한국어 폰트 유무를 검사합니다. 실제 브라우저 바이너리·폰트 파일·OS 정보도 fingerprint에 포함하여 환경이 바뀌면 캐시를 무효화합니다. 공식 MCR 응답에서 확인한 이미지 digest `sha256:6446946a1d9fd62d9ae501312a2d76a43ee688542b21622056a372959b65d63d`로 컨테이너를 고정합니다. Node 버전과 워크플로 설정도 fingerprint에 포함합니다.

- Chromium 1280×800, DPR 1, 한국어 locale, Asia/Seoul, 밝은 테마, reduced motion.
- DOM 로드 후 폰트·이미지를 최대 1.5초 대기합니다. navigation 제한 6.5초, screenshot 제한 3초. 무한 networkidle 대기와 임의 초기 조작은 없습니다.
- CSS 애니메이션·전환을 정지합니다. 무작위 값·시각·canvas의 완전 동일성은 보장하지 않습니다.
- 작품별 독립 Node 프로세스·브라우저·임시 HOME·새 컨텍스트, 최대 2개 동시 처리. 시작부터 촬영과 브라우저 종료까지 외부 15초 watchdog을 적용합니다. 초과 시 Linux 프로세스 그룹을 SIGKILL해 브라우저 자식도 종료합니다.
- 환경변수는 PATH·임시 HOME/캐시·locale·브라우저 경로만 전달합니다. Actions 토큰이나 proxy 비밀값을 전달하지 않습니다.
- Service Worker 차단, 선택한 로컬 작품 URL/index.html 외 HTTP 차단, 모든 WebSocket 차단, 팝업 종료·다운로드 취소·대화상자 dismiss와 이벤트 기록.
- 웹서버는 새로 조립한 공개 staging만 제공합니다. 원본 checkout·`.git`·스크립트·워크플로·로그를 제공하지 않습니다.
- 이미지 PNG 팔레트 최적화로 200KB 이하를 목표로 합니다. 초과하면 숨기지 않고 경고합니다.
- HTML 원문, 학번·`/sih26/학번/` 경로, 촬영 스크립트·파이프라인, lockfile, 브라우저 바이너리, OS, 폰트, 화면·이미지 설정을 fingerprint로 사용합니다. PNG 파일명은 fingerprint와 **이미지 내용 해시**를 모두 포함하므로 강제 촬영 결과가 바뀌면 주소도 바뀝니다.
- 생성물은 `dist/projects.json`, `dist/thumbnails/학번-fingerprint-이미지해시.png`, `dist/build-info.json`입니다. 산출물·캐시는 자동 커밋하지 않습니다. 현재 존재하는 작품만 복사합니다.
- `build-info.json`과 화면 하단은 적용 SHA·산출물 시각만 알려줍니다. 정적 화면이 이후 빌드 실패를 실시간 감지하지는 않습니다.

200작품 촬영 30분, Actions 빌드 40분이 목표입니다. 성능 테스트는 단순한 200개 fixture의 측정이며 모든 실제 2MiB 작품의 성능을 보증하지 않습니다.

## 개발·검증

```sh
npm ci
npx playwright install --with-deps chromium
npm test
npm run test:browser
npm run test:capture
npm run test:detail
npm run test:scale
npm run build
npm run serve
```

테스트·촬영은 Linux 프로세스 그룹 종료와 fontconfig를 사용합니다. Windows에서는 WSL 또는 위 Linux 컨테이너를 사용하세요. `npm run serve`는 **dist만** `/sih26/` 접두사로 제공합니다. 개발용 Node/Playwright/sharp/parse5는 배포 페이지에서 로드하지 않습니다. 사이트 JS/CSS를 수정한 뒤 다시 build하세요.

표준 브라우저 다운로드가 막힌 클라우드에서는 설치된 브라우저를 `CAPTURE_BROWSER=/usr/lib/chromium/chromium`으로 지정할 수 있습니다. 이는 CI의 고정 Chromium과 다른 환경이므로 측정 결과에 구분해 기록합니다. 브라우저 다운로드를 위해 TLS·체크섬 검증을 끄지 마세요.

테스트 작품은 OS 임시 폴더에 만들고 종료 시 삭제합니다. 실제 전시판에 가짜 학생 작품은 포함하지 않습니다. 테스트 결과는 `test-results/`에 저장합니다. `npm test`는 카탈로그와 입력 검증, `test:browser`는 브라우저 UI·촬영 실패·캐시, `test:detail`은 상세 화면의 모바일·키보드 검사, `test:capture`는 외부 요청 차단·캐시 복구·강제 재촬영·삭제 산출물, `test:scale`은 200작품 cold/warm 측정입니다. 구체적인 현재 결과는 `VALIDATION.md`를 참고하세요.

## 개인정보·보안·접근성 범위

공개 저장소·Pages에 학번, 코드, 스크린샷, PRD와 Git 이력이 공개됩니다. 이름·전화번호·실제 학생 데이터·API 키를 넣지 마세요. 기획서는 공개용으로 정리하고 예시 데이터는 가상 데이터를 쓰세요. 유출 시 파일 삭제만으로 Git 이력에서 제거되지 않으므로 별도 대응이 필요합니다.

작품 실행 iframe의 sandbox는 `allow-scripts allow-forms`만 허용합니다. same-origin·상위 페이지 이동 권한을 추가하지 않습니다. 문서 load는 정상 작동 증거가 아닙니다. 흰 화면·내부 오류의 완전 자동 진단은 불가능합니다. 저장·팝업·다운로드 검증은 새 탭에서 합니다. 새 탭의 학생 작품들은 같은 사이트 origin을 공유하므로 저장 키 접두사는 충돌 예방 규칙이지 보안 격리가 아닙니다. 교사가 검토한 작품만 공개하세요.

전시판은 360px, 반응형 1~4열, 주요 대상 44px, label·focus·aria-live를 제공합니다. 전시판 접근성과 학생 작품 내부 접근성은 별개입니다. WCAG AA를 목표로 했으나 인증이나 모든 보조공학 조합의 적합성까지 주장하지 않습니다.
