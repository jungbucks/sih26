# SIH26 · 학생 프로그램 전시판

HTML·CSS·순수 JavaScript로 만든 고등학교 정보 수업용 전시판입니다. 실행 시 서버 API·DB·로그인·외부 CDN·AI API를 사용하지 않습니다. 목록에는 스크린샷만 표시하고 상세에서 요청한 작품 하나만 sandbox iframe으로 실행합니다.

## 현재 저장소와 최초 게시

확인한 origin은 `github.com/jungbucks/sih26`입니다. 구현 시작 시 원격에는 커밋·브랜치가 없어서 기본 브랜치를 확인할 수 없었습니다. `main`이라고 가정해 워크플로를 고정하지 않았습니다.

1. 구현 파일을 저장소에 첫 커밋으로 올리고 GitHub에서 기본 브랜치를 지정합니다. 학생 HTML은 교사가 확인한 코드만 기본 브랜치에 반영합니다.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions**를 선택합니다.
3. Actions 사용을 허용하고 `github-pages` 배포 환경의 보호 규칙을 확인합니다. 기본 브랜치만 배포할 수 있게 제한하는 것을 권장합니다.
4. 기본 브랜치 push 또는 **Actions → Build and publish exhibition → Run workflow**를 실행합니다.
5. build 성공 후 deploy 성공과 **게시 완료** 요약의 실제 주소를 확인합니다. 빌드 성공만으로 게시되었다고 판단하지 않습니다.

기본 Pages 규칙에 따른 예상 주소는 `https://jungbucks.github.io/sih26/`입니다. 실제 게시와 이 주소의 응답은 아직 확인되지 않았습니다. 배포 출력 주소가 최종 근거입니다. 외부 PR 실행 트리거와 `pull_request_target`은 없습니다. 빌드는 contents 읽기만, 배포는 contents 읽기·pages 쓰기·id-token 쓰기만 사용합니다. 동일 게시 흐름은 이전 실행을 취소하며 배포 직전 기본 브랜치 최신 SHA인지 API로 재확인합니다. 그 직후 새 push가 오는 극히 짧은 경쟁 구간까지 원자적으로 막는 GitHub Pages 기능은 없으므로 concurrency 취소도 함께 사용합니다.

## 작품 추가·교체·삭제

루트 바로 아래 **숫자 5자리 폴더**의 `index.html`만 등록합니다. 앞자리 0을 보존합니다.

```text
20100/index.html
20101/index.html
prd/20100.md          # 선택, 공개용 원문
project-meta.json    # 선택, 교사 덮어쓰기
```

- **추가:** 학번 폴더에 CSS·JS와 필요한 이미지/데이터를 내장한 단일 `index.html`을 넣고 기본 브랜치에 push합니다.
- **수정:** 해당 파일을 완전한 HTML로 교체합니다. 다른 학생 파일은 건드리지 않습니다.
- **삭제:** 폴더 또는 그 안의 index.html을 삭제하고 push합니다. 매번 현재 파일로 산출물을 새로 조립하므로 예전 캐시가 작품을 다시 등록하지 않습니다.
- **이름 변경:** 기존 학번 삭제 + 새 학번 등록으로 처리합니다.
- **임시 비공개:** 무한 루프 등 문제가 재현되면 `index.html`을 `index.disabled.html`로 이름 변경하거나 학생 폴더를 숫자 5자리가 아닌 이름으로 바꿉니다. 새 게시 후 목록과 공개 산출물에서 제외됩니다. 공개 저장소의 Git 이력까지 비공개가 되는 것은 아닙니다.
- 루트 `20100.html`, 하위 폴더 내부 작품, 루트 전시판은 자동 등록하지 않습니다. 폴더만 있거나 HTML이 2MiB를 초과하면 이유와 학번을 보고하고 나머지를 처리합니다. 심볼릭 링크는 작품으로 사용하지 않습니다.
- 등록 가능한 작품이 **200개 초과**하면 전체 빌드를 실패시킵니다. 임의로 일부를 누락해 게시하지 않습니다.

파일 하나를 내려받아 오프라인에서 기본 기능을 쓸 수 있도록 외부 라이브러리·외부 리소스에 의존하지 마세요. 촬영 중 외부 요청은 차단합니다. 빌드 도구는 학생 작품의 모든 실행 경로가 오프라인에서 동작하는지 자동으로 증명하지 않습니다.

### HTML 메타 예시

```html
<!doctype html>
<html lang="ko">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <title>나의 시간표 도우미</title>
  <meta name="description" content="하루의 수업과 준비물을 정리합니다.">
  <meta name="class" content="2학년 1반">
  <style>/* 스타일 */</style>
</head>
<body>
  <h1>시간표 도우미</h1>
  <p>수업을 추가해 보세요.</p>
  <script>/* 예시 데이터·상태·처리 함수·화면 갱신·이벤트 */</script>
</body>
</html>
```

반은 학번에서 추론하지 않습니다. 상태도 자동 추론하지 않습니다. 수정일은 학생 index.html의 마지막 Git 커밋 시각이며 한국 시간으로 표시합니다. 미커밋 파일은 ‘수정일 미확인’입니다. 사이트 빌드 시각으로 대체하지 않습니다.

### 선택 JSON과 검증 규칙

```json
{
  "20100": {
    "title": "시간표 도우미",
    "description": "친구들의 의견을 반영한 시간표 프로그램입니다.",
    "class": "2학년 1반",
    "status": "개선 중",
    "changes": "빈 입력 안내와 키보드 이동을 개선했습니다."
  }
}
```

최상위는 학번을 키로 하는 객체, 각 값도 객체입니다. 허용 필드는 아래뿐이며 **모두 문자열**입니다. JSON 구문·구조·자료형·허용값·길이 오류는 게시 전 전체 실패입니다. 공백 연속(줄바꿈 포함)은 한 칸으로 합치고 앞뒤 공백을 제거합니다. 길이는 정리 후 Unicode 코드 포인트 수입니다.

| 필드 | 최대 길이 | 비었거나 없을 때 |
|---|---:|---|
| title | 100 | 프로젝트 학번 |
| description | 300 | 프로그램을 실행해 확인해 보세요. |
| class | 40 | 미분류 |
| status | 10 | 미표시. 첫 버전 / 개선 중 / 개선 완료만 허용 |
| changes | 500 | 미표시 |

HTML에서 추출한 값에도 같은 공백 규칙을 적용하고 상한까지 잘라 표시합니다. 선택 JSON은 초과 시 오류를 내므로 교사가 수정할 수 있습니다. JSON 값이 HTML 값을 덮어씁니다. 빈 덮어쓰기 값은 기본값으로 돌아갑니다. 존재하지 않는 작품의 유효한 메타는 작품을 새로 등록하지 않습니다. 제목·설명·기획서는 `textContent` 또는 textarea로 표시합니다.

### 공개 기획서 예시

`prd/20100.md`:

```markdown
# 시간표 도우미
- 목적: 준비물을 잊지 않도록 돕기
- 대상: 같은 반 학생
- 핵심 기능: 시간표 입력, 준비물 목록
- 확인할 상황: 빈 입력, 중복 수업, 저장 불가
- 개인정보: 이름과 연락처를 수집하지 않음
```

Markdown을 HTML로 변환하지 않고 원문으로 보여주며 파일 다운로드를 제공합니다. 없으면 ‘기획서는 아직 등록되지 않았습니다.’라고 안내합니다.

## 교사 처리 결과와 재촬영

Actions 실행 Summary에서 실행 SHA, 등록·제외 수, 새 촬영·캐시·실패 수, 제외·실패 학번과 이유, 후속 조치를 확인합니다. 자세한 이벤트 기록은 `build-report` 아티팩트에 있습니다. 로컬 결과는 `.cache/build-report.json`입니다. 내부 로그는 사이트에 포함하지 않습니다.

수동 workflow의 `force` 입력:

- 빈 값: 일반 갱신, 성공 캐시 재사용
- `20100`: 그 학번만 강제 재촬영
- `all`: 전체 강제 재촬영

개별 촬영 실패는 이미지 없음 대체 화면으로 표시하지만 정보·실행·다운로드는 유지합니다. 실패 이미지는 캐시하지 않아 다음 실행에서 재시도합니다. 메타 오류·200개 초과·브라우저 설치 오류 등 전체 실패 시 배포 작업은 실행되지 않아 기존 게시본을 유지합니다. 잘못된 변경은 GitHub 커밋의 **Revert** 또는 `git revert <커밋>` 후 기본 브랜치에 반영합니다. 공유 이력을 강제로 초기화하지 마세요.

## 촬영·캐시·공개 산출물

Actions는 Playwright **1.58.2**, `mcr.microsoft.com/playwright:v1.58.2-noble`, Node **22.16.0**을 사용합니다. 이미지에 포함된 한국어 폰트 유무를 검사합니다. 실제 브라우저 바이너리·폰트 파일·OS 정보도 fingerprint에 포함하여 환경이 바뀌면 캐시를 무효화합니다. 공식 MCR 응답에서 확인한 이미지 digest `sha256:6446946a1d9fd62d9ae501312a2d76a43ee688542b21622056a372959b65d63d`로 컨테이너를 고정합니다. Node 버전과 워크플로 설정도 fingerprint에 포함합니다.

- Chromium 1280×800, DPR 1, 한국어 locale, Asia/Seoul, 밝은 테마, reduced motion.
- DOM 로드 후 폰트·이미지를 최대 1.5초 대기합니다. navigation 제한 6.5초, screenshot 제한 3초. 무한 networkidle 대기와 임의 초기 조작은 없습니다.
- CSS 애니메이션·전환을 정지합니다. 무작위 값·시각·canvas의 완전 동일성은 보장하지 않습니다.
- 작품별 독립 Node 프로세스·브라우저·임시 HOME·새 컨텍스트, 최대 2개 동시 처리. 시작부터 촬영과 브라우저 종료까지 외부 15초 watchdog을 적용합니다. 초과 시 Linux 프로세스 그룹을 SIGKILL해 브라우저 자식도 종료합니다.
- 환경변수는 PATH·임시 HOME/캐시·locale·브라우저 경로만 전달합니다. Actions 토큰이나 proxy 비밀값을 전달하지 않습니다.
- Service Worker 차단, 선택한 로컬 작품 URL/index.html 외 HTTP 차단, 모든 WebSocket 차단, 팝업 종료·다운로드 취소·대화상자 dismiss와 이벤트 기록.
- 웹서버는 새로 조립한 공개 staging만 제공합니다. 원본 checkout·`.git`·스크립트·워크플로·로그를 제공하지 않습니다.
- 이미지 PNG 팔레트 최적화로 200KB 이하를 목표로 합니다. 초과하면 숨기지 않고 경고합니다.
- HTML 원문, 학번·`/sih26/학번/` 경로, 촬영 스크립트·파이프라인, lockfile, 브라우저 바이너리, OS, 폰트, 화면·이미지 설정을 fingerprint로 사용합니다. PNG 파일명은 fingerprint와 **이미지 내용 해시**를 모두 포함하므로 강제 촬영 결과가 바뀌면 주소도 바뀝니다.
- 생성물은 `dist/projects.json`, `dist/thumbnails/학번-fingerprint-이미지해시.png`, `dist/build-info.json`입니다. 산출물·캐시는 자동 커밋하지 않습니다. 현재 존재하는 작품만 복사합니다.
- `build-info.json`과 화면 하단은 적용 SHA·산출물 시각만 알려줍니다. 정적 화면이 이후 빌드 실패를 실시간 감지하지는 않습니다.

200작품 촬영 30분, Actions 빌드 40분이 목표입니다. 성능 테스트는 단순한 200개 fixture의 측정이며 모든 실제 2MiB 작품의 성능을 보증하지 않습니다.

## 개발·검증

```sh
npm ci
npx playwright install --with-deps chromium
npm test
npm run test:browser
npm run test:capture
npm run test:detail
npm run test:scale
npm run build
npm run serve
```

테스트·촬영은 Linux 프로세스 그룹 종료와 fontconfig를 사용합니다. Windows에서는 WSL 또는 위 Linux 컨테이너를 사용하세요. `npm run serve`는 **dist만** `/sih26/` 접두사로 제공합니다. 개발용 Node/Playwright/sharp/parse5는 배포 페이지에서 로드하지 않습니다. 사이트 JS/CSS를 수정한 뒤 다시 build하세요.

표준 브라우저 다운로드가 막힌 클라우드에서는 설치된 브라우저를 `CAPTURE_BROWSER=/usr/lib/chromium/chromium`으로 지정할 수 있습니다. 이는 CI의 고정 Chromium과 다른 환경이므로 측정 결과에 구분해 기록합니다. 브라우저 다운로드를 위해 TLS·체크섬 검증을 끄지 마세요.

테스트 작품은 OS 임시 폴더에 만들고 종료 시 삭제합니다. 실제 전시판에 가짜 학생 작품은 포함하지 않습니다. 테스트 결과는 `test-results/`에 저장합니다. `npm test`는 카탈로그와 입력 검증, `test:browser`는 브라우저 UI·촬영 실패·캐시, `test:detail`은 상세 화면의 모바일·키보드 검사, `test:capture`는 외부 요청 차단·캐시 복구·강제 재촬영·삭제 산출물, `test:scale`은 200작품 cold/warm 측정입니다. 구체적인 현재 결과는 `VALIDATION.md`를 참고하세요.

```text

작품 제목·설명·반 메타 → 스타일 → 화면 구조 → 예시 데이터와 설정값 →
데이터·상태 → 처리 함수 → 화면 갱신 → 이벤트 연결.

이름이 명확한 함수로 나누고 이벤트 리스너를 사용하세요.

예시 데이터와 설정값은 한곳에 모으고 첫 화면에 예시나 사용 안내를 보여 주세요.
핵심 기능 2~3개를 우선하고 불필요한 알고리즘을 억지로 추가하지 마세요.

localStorage.clear()를 사용하지 말고 자신의 키만 삭제하세요.
저장 예외를 처리해 저장 불가 환경에서도 기본 기능이 동작하게 하세요.
```
